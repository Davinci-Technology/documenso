## Prerequisites

For a self-contained setup that includes PostgreSQL, see [Docker Compose Deployment](/docs/self-hosting/deployment/docker-compose).

Before starting, ensure you have:

- [Docker](https://docs.docker.com/get-docker/) 20.10 or later installed
- A PostgreSQL 14+ database accessible from your Docker host
- SMTP credentials for sending emails
- At least 1GB of available RAM

Verify Docker is installed:

```bash
docker --version
```

## Pulling the Docker Image

The Davinci Sign image is available on both DockerHub and GitHub Container Registry:

```bash
# DockerHub
docker pull davinci/davinci-sign:latest

# GitHub Container Registry
docker pull ghcr.io/davinci/davinci-sign:latest
```

### Available Tags

| Tag       | Description                      |
| --------- | -------------------------------- |
| `latest`  | Latest stable release            |
| `x.y.z`   | Specific version (e.g., `1.5.0`) |
| `release` | Latest release branch build      |

<Callout type="info">
  Pin to a specific version tag in production to avoid unexpected updates.
</Callout>

## Environment Variables

### Required Variables

These variables must be set for Davinci Sign to start:

| Variable                                | Description                                                                 | Default                       |
| --------------------------------------- | --------------------------------------------------------------------------- | ----------------------------- |
| `NEXTAUTH_SECRET`                       | Secret key for session encryption. Generate with `openssl rand -base64 32`  | -                             |
| `NEXT_PRIVATE_ENCRYPTION_KEY`           | Primary encryption key (minimum 32 characters)                              | -                             |
| `NEXT_PRIVATE_ENCRYPTION_SECONDARY_KEY` | Secondary encryption key (minimum 32 characters)                            | -                             |
| `NEXT_PUBLIC_WEBAPP_URL`                | Public URL where Davinci Sign is accessible (e.g., `https://sign.example.com`) | -                             |
| `NEXT_PRIVATE_INTERNAL_WEBAPP_URL`      | Internal URL the app uses to call itself (for background jobs)              | Same as `NEXT_PUBLIC_WEBAPP_URL` |
| `NEXT_PRIVATE_DATABASE_URL`             | PostgreSQL connection string                                                | -                             |
| `NEXT_PRIVATE_SMTP_TRANSPORT`           | Email transport: `smtp-auth`, `smtp-api`, `resend`, or `mailchannels`       | `smtp-auth`                   |
| `NEXT_PRIVATE_SMTP_FROM_NAME`           | Sender name for outgoing emails                                             | -                             |
| `NEXT_PRIVATE_SMTP_FROM_ADDRESS`        | Sender email address                                                        | -                             |

### Database Connection

Davinci Sign requires two database connection strings:

| Variable                           | Required     | Default                     | Description                       |
| ---------------------------------- | ------------ | --------------------------- | --------------------------------- |
| `NEXT_PRIVATE_DATABASE_URL`        | Yes          | -                           | Pooled connection for app queries |
| `NEXT_PRIVATE_DIRECT_DATABASE_URL` | When pooling | `NEXT_PRIVATE_DATABASE_URL` | Direct connection for migrations  |

Connection string format:

```
postgresql://user:password@host:5432/database
```

If you're not using a connection pooler like PgBouncer, both variables can use the same connection string.

### SMTP Configuration

For `smtp-auth` transport:

| Variable                     | Required | Default     | Description                           |
| ---------------------------- | -------- | ----------- | ------------------------------------- |
| `NEXT_PRIVATE_SMTP_HOST`     | Yes      | `127.0.0.1` | SMTP server hostname                  |
| `NEXT_PRIVATE_SMTP_PORT`     | Yes      | `587`       | SMTP server port (usually 587 or 465) |
| `NEXT_PRIVATE_SMTP_USERNAME` | Yes      | -           | SMTP username                         |
| `NEXT_PRIVATE_SMTP_PASSWORD` | Yes      | -           | SMTP password                         |
| `NEXT_PRIVATE_SMTP_SECURE`   | No       | `false`     | Set to `true` to force TLS            |

See [Email Configuration](/docs/self-hosting/configuration/email) for other transport options.

### Optional Variables

| Variable                                    | Description                                                    | Default                   |
| ------------------------------------------- | -------------------------------------------------------------- | ------------------------- |
| `PORT`                                      | Port the application listens on                                | `3000`                    |
| `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH`      | Path to signing certificate inside container — set to the volume-mount path (e.g. `/opt/davinci-sign/cert.p12`). Only Docker Compose defaults this; plain `docker run` must set it explicitly | -                         |
| `NEXT_PRIVATE_SIGNING_PASSPHRASE`           | Passphrase for the signing certificate                         | -                         |
| `NEXT_PRIVATE_SIGNING_LOCAL_FILE_CONTENTS`  | Base64-encoded `.p12` certificate (alternative to file path)   | -                         |
| `NEXT_PUBLIC_UPLOAD_TRANSPORT`              | Document storage: `database` or `s3`                           | `database`                |
| `NEXT_PUBLIC_DISABLE_SIGNUP`                | Master switch — disable all signup methods                     | `false`                   |
| `NEXT_PUBLIC_ALLOW_SIGNUP`                  | Allow email/password registration                               | `true`                    |
| `NEXT_PUBLIC_FEATURE_GOOGLE_SSO_ENABLED`    | Enable Google OAuth signup                                     | `false`                   |
| `NEXT_PUBLIC_FEATURE_GITHUB_SSO_ENABLED`    | Enable GitHub OAuth signup                                     | `false`                   |
| `NEXT_PUBLIC_FEATURE_OIDC_SSO_ENABLED`      | Enable generic OpenID Connect SSO                             | `false`                   |
| `NEXT_PUBLIC_FEATURE_SAML_SSO_ENABLED`      | Enable SAML SSO                                               | `false`                   |
| `NEXT_PUBLIC_FEATURE_SIGNATURE_PAD_ENABLED` | Enable signature pad                                           | `true`                    |
| `NEXT_PUBLIC_FEATURE_TEXT_SIGNATURE_ENABLED` | Enable text signature                                         | `true`                    |
| `NEXT_PRIVATE_STRIPE_API_KEY`               | Stripe API key for billing                                     | -                         |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`        | Stripe publishable key                                         | -                         |
| `NEXT_PRIVATE_STRIPE_WEBHOOK_SECRET`        | Stripe webhook endpoint secret                                 | -                         |

<Callout type="warn">
  Setting `NEXT_PUBLIC_DISABLE_SIGNUP=true` overrides all other signup controls and completely prevents new user registration.
</Callout>

### S3 Storage (Optional)

For S3 document storage (`NEXT_PUBLIC_UPLOAD_TRANSPORT=s3`):

| Variable                          | Description                           | Default                         |
| --------------------------------- | ------------------------------------- | ------------------------------- |
| `NEXT_PRIVATE_UPLOAD_PROVIDER`    | S3 provider: `s3`, `r2`               | `s3`                            |
| `NEXT_PRIVATE_UPLOAD_REGION`      | AWS region or R2 location             | `us-east-1`                     |
| `NEXT_PRIVATE_UPLOAD_BUCKET`      | S3 bucket name                        | -                               |
| `NEXT_PRIVATE_UPLOAD_ACCESS_KEY_ID` | AWS/R2 access key                   | -                               |
| `NEXT_PRIVATE_UPLOAD_SECRET_ACCESS_KEY` | AWS/R2 secret key              | -                               |
| `NEXT_PRIVATE_UPLOAD_ENDPOINT`    | Custom S3 endpoint (for R2/MinIO)     | Auto-detected based on provider |

#### GitHub OAuth

| `NEXT_PRIVATE_GITHUB_CLIENT_SECRET`     | GitHub OAuth client secret      |

#### Generic OpenID Connect

| Variable                            | Description                           |
| ----------------------------------- | ------------------------------------- |
| `NEXT_PUBLIC_FEATURE_OIDC_SSO_ENABLED` | Set to `true`                       |
| `NEXT_PRIVATE_OIDC_CLIENT_ID`       | OIDC client ID                        |
| `NEXT_PRIVATE_OIDC_CLIENT_SECRET`   | OIDC client secret                    |
| `NEXT_PRIVATE_OIDC_WELL_KNOWN`      | OIDC discovery endpoint URL           |

#### SAML SSO

| Variable                               | Description                        |

### Background Jobs & Performance

| Variable                              | Description                            | Default |
| ------------------------------------- | -------------------------------------- | ------- |
| `NEXT_PRIVATE_BACKGROUND_JOB_CONCURRENCY` | Max concurrent background jobs     | `5`     |

<Callout type="info">
  Adjust `BACKGROUND_JOB_CONCURRENCY` based on your server resources. Higher values process jobs faster but use more CPU and memory.
</Callout>

## Running the Container

### Basic Example

```bash
docker run -d \
  --name documenso \
  -p 3000:3000 \
  -e NEXTAUTH_SECRET="your-secret-key-here" \
  -e NEXT_PRIVATE_ENCRYPTION_KEY="your-32-char-encryption-key" \
  -e NEXT_PRIVATE_ENCRYPTION_SECONDARY_KEY="your-32-char-secondary-key" \
  -e NEXT_PUBLIC_WEBAPP_URL="https://your-domain.com" \
  -e NEXT_PRIVATE_DATABASE_URL="postgresql://user:pass@db:5432/documenso" \
  -e NEXT_PRIVATE_SMTP_TRANSPORT="smtp-auth" \
  -e NEXT_PRIVATE_SMTP_HOST="smtp.example.com" \
  -e NEXT_PRIVATE_SMTP_PORT="587" \
  -e NEXT_PRIVATE_SMTP_USERNAME="your-username" \
  -e NEXT_PRIVATE_SMTP_PASSWORD="your-password" \
  -e NEXT_PRIVATE_SMTP_FROM_NAME="Davinci Sign" \
  -e NEXT_PRIVATE_SMTP_FROM_ADDRESS="noreply@davincisolutions.ai" \
  davinci/davinci-sign:latest
```

### With Certificate Volume

For PDF signing capabilities, mount your `.p12` certificate:

```bash
docker run -d \
  --name documenso \
  -p 3000:3000 \
  -v /host/path/to/cert.p12:/opt/davinci-sign/cert.p12:ro \
  -e NEXTAUTH_SECRET="your-secret-key-here" \
  -e NEXT_PRIVATE_ENCRYPTION_KEY="your-32-char-encryption-key" \
  -e NEXT_PRIVATE_ENCRYPTION_SECONDARY_KEY="your-32-char-secondary-key" \
  -e NEXT_PUBLIC_WEBAPP_URL="https://your-domain.com" \
  -e NEXT_PRIVATE_DATABASE_URL="postgresql://user:pass@db:5432/documenso" \
  -e NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH="/opt/davinci-sign/cert.p12" \
  -e NEXT_PRIVATE_SIGNING_PASSPHRASE="your-cert-passphrase" \
  -e NEXT_PRIVATE_SMTP_TRANSPORT="smtp-auth" \
  -e NEXT_PRIVATE_SMTP_HOST="smtp.example.com" \
  -e NEXT_PRIVATE_SMTP_PORT="587" \
  -e NEXT_PRIVATE_SMTP_USERNAME="your-username" \
  -e NEXT_PRIVATE_SMTP_PASSWORD="your-password" \
  -e NEXT_PRIVATE_SMTP_FROM_NAME="Davinci Sign" \
  -e NEXT_PRIVATE_SMTP_FROM_ADDRESS="noreply@davincisolutions.ai" \
  davinci/davinci-sign:latest
```

### Environment File

Create a `.env` file for easier management:

```bash
# .env
NEXTAUTH_SECRET=your-secret-key-here
NEXT_PRIVATE_ENCRYPTION_KEY=your-32-char-encryption-key
NEXT_PRIVATE_ENCRYPTION_SECONDARY_KEY=your-32-char-secondary-key
NEXT_PUBLIC_WEBAPP_URL=https://your-domain.com
NEXT_PRIVATE_DATABASE_URL=postgresql://user:pass@db:5432/documenso
NEXT_PRIVATE_SMTP_TRANSPORT=smtp-auth
NEXT_PRIVATE_SMTP_HOST=smtp.example.com
NEXT_PRIVATE_SMTP_PORT=587
NEXT_PRIVATE_SMTP_USERNAME=your-username
NEXT_PRIVATE_SMTP_PASSWORD=your-password
NEXT_PRIVATE_SMTP_FROM_NAME=Davinci Sign
NEXT_PRIVATE_SMTP_FROM_ADDRESS=noreply@davincisolutions.ai
NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH=/opt/davinci-sign/cert.p12
NEXT_PRIVATE_SIGNING_PASSPHRASE=your-cert-passphrase
```

Then run:

```bash
docker run -d \
  --name documenso \
  -p 3000:3000 \
  -v /host/path/to/cert.p12:/opt/davinci-sign/cert.p12:ro \
  --env-file .env \
  davinci/davinci-sign:latest
```

## Health Checks & Monitoring

The container exposes a health check endpoint at `/api/health`:

```bash
# Check if the container is healthy
curl http://localhost:3000/api/health
```

Add a Docker health check:

```bash
docker run -d \
  --name documenso \
  --health-cmd="curl -f http://localhost:3000/api/health || exit 1" \
  --health-interval=30s \
  --health-timeout=10s \
  --health-retries=3 \
  -p 3000:3000 \
  --env-file .env \
  davinci/davinci-sign:latest
```

## Upgrading

<Steps>

<Step>

**Stop the existing container**

```bash
docker stop documenso
```

</Step>

<Step>

**Pull the new image**

```bash
docker pull davinci/davinci-sign:latest
```

</Step>

<Step>

**Remove the old container**

```bash
docker rm documenso
```

</Step>

<Step>

**Start with the new image**

```bash
docker run -d \
  --name documenso \
  --env-file .env \
  davinci/davinci-sign:latest
```

</Step>

</Steps>

Database migrations run automatically when the new container starts.

<Callout type="warn">
  Always backup your database before upgrading, especially for major version changes.
</Callout>

## Troubleshooting

<Accordions>
<Accordion title="Container won't start">

Check the logs for specific error messages:

```bash
docker logs documenso
```

Common issues:
- Missing required environment variables
- Database connection failures
- Invalid SMTP configuration
- Port conflicts (3000 already in use)

</Accordion>

<Accordion title="Database connection errors">

Verify your database is reachable:

```bash
# Test from the Docker host
telnet your-db-host 5432

# Test from inside the container
docker exec -it documenso sh
nc -zv your-db-host 5432
```

Check your connection string format:
```
postgresql://username:password@hostname:5432/database_name
```

</Accordion>

<Accordion title="SMTP/Email issues">

Test SMTP connectivity:

```bash
docker exec -it documenso sh
nc -zv your-smtp-host 587
```

Enable SMTP debugging by adding:
```bash
-e NODE_TLS_REJECT_UNAUTHORIZED=0  # For self-signed certificates (dev only)
```

</Accordion>

<Accordion title="PDF signing not working">

Ensure your certificate is:
- Valid and not expired
- Mounted correctly (`-v host/path:/container/path`)
- Readable by the container user
- In the correct format (`.p12`)

Test certificate mounting:

```bash
docker exec -it documenso ls -la /opt/davinci-sign/cert.p12
```

</Accordion>

<Accordion title="Performance issues">

Monitor resource usage:

```bash
docker stats documenso
```

Consider:
- Increasing container memory limits
- Reducing `BACKGROUND_JOB_CONCURRENCY`
- Using a more powerful database
- Enabling connection pooling

</Accordion>
</Accordions>
